# StudentSphere QA — Student Management System Testing

## 📌 Project Overview

StudentSphere QA is an academic-level manual software testing project focused on validating the core functionalities of a Student Management System.

The project demonstrates fundamental QA practices, including test planning, test case design, functional validation, defect documentation, and test execution reporting.

## 🎯 Project Objectives

- Understand the fundamentals of manual software testing.
- Design and organize test cases based on application requirements.
- Validate positive and negative test scenarios.
- Document and track defects systematically.
- Maintain requirement-to-test-case traceability.
- Prepare structured test execution reports.

## 🧪 Testing Scope

The following functionalities are included where supported by the application:

- User login and authentication
- Adding student records
- Viewing and searching student details
- Updating student information
- Deleting student records
- Input validation and error handling

## 🔍 Testing Types

- Functional Testing
- Positive Testing
- Negative Testing
- UI Validation
- Boundary Value Testing, where applicable

## 🛠️ Tools and Technologies

- **Microsoft Excel / Google Sheets:** Test cases, test data, and defect tracking
- **GitHub:** Version control and project documentation
- **Manual Testing:** Functional validation and test execution

## 📂 Project Deliverables

| Deliverable | Description |
|---|---|
| Test Plan | Defines the testing objectives, scope, and approach |
| Test Cases | Contains test steps, test data, and expected results |
| Test Data | Provides input values for test scenarios |
| Bug Reports | Documents reproducible defects |
| RTM | Maps requirements to corresponding test cases |
| Execution Summary | Records test results and execution status |

## ⚙️ Test Execution Process

1. Review the available requirements and application functionality.
2. Identify test scenarios.
3. Prepare test cases and test data.
4. Execute the test cases manually.
5. Compare actual results with expected results.
6. Document reproducible defects.
7. Update the execution summary and test status.

## 📊 Test Status Definitions

- **Pass:** Actual result matches the expected result.
- **Fail:** Actual result differs from the expected result.
- **Blocked:** Execution cannot continue because of a dependency or issue.
- **Not Executed:** The test case has not yet been executed.
